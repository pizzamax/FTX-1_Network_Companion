# FTX-1 Network Companion

*Built for hams by a lazy ham*

[English](README.md) | **日本語**

![FTX-1 Network Companion のブラウザ画面: S メーター、VFO 表示、スコープ、FT8 デコーダー（画面内のコールサインはダミーです）](docs/screenshot.png)

日々刻々と変わる電波伝搬のコンディションが、気になって仕方がない。そんな時がありませんか。
今のバンドは開けているのか、あの局はまだ聞こえているのか。確かめたいけれど、リグのある部屋まで腰を上げるのも、ましてアンテナの前に陣取るのも億劫だ――。

これは、そんな時のための仕組みです。リグは今までどおり所定の場所に置いたまま、家の中のどこからでも、PC や Mac のブラウザひとつで、周波数やモードを切り替え、受信音を聴き、S メーターで信号の強さを確かめ、FT8 のデコード結果まで眺められます。
立ち上がるのは、部屋のソファの上、あるいは夕食後のコーヒーの傍らで構いません。ものぐさな HAM にこそ、うってつけの一台です。

なお、ネットワーク越しに電波を出させることはできないよう、意図して設計してあります（詳細は「電波を送信させないための制限」）。ここは「聴くための道具」です。

## 概要

Wi-Fi が使える小さなマイコン基板「ESP32-S3」を Yaesu FTX-1 に USB でつなぎ、リグの受信音や状態を Wi-Fi 経由で手元の PC / Mac に届けるためのファームウェアです。

- **音声**: FTX-1 の USB オーディオ（受信音）を、ESP32-S3 が Wi-Fi でブラウザへ流します。パソコンにつなぐと「USB マイク」のように見える、標準的な USB オーディオ規格（UAC 1.0）のデバイスとして使えます。
- **操作と状態**: FTX-1 の USB シリアルを通じて、周波数やモードの切り替え、S メーターなどの読み取りをブラウザから行います。この、パソコンから無線機を操作・監視する仕組みを **CAT**（Computer Aided Transceiver）と呼びます。
- **FT8**: 受信音のデコードは、ブラウザの中で行います。

PC / Mac 側に必要なのは、同じ LAN につながったブラウザだけです。専用のソフトは要りません。

```
FTX-1
 ├─ USB Audio (UAC 1.0) ──────────> ESP32-S3 ──Wi-Fi / HTTPS──> ブラウザ / ffplay / VLC
 └─ USB Serial (CP210x / CAT) ────>            ├─ 音声ストリーミング（PCM / WAV）
                                               ├─ ブラウザ内 FT8 リアルタイムデコーダー
                                               ├─ CAT 制御（周波数・モード・スケルチ等）
                                               └─ OTA ファームウェア更新
```

> 図中の「OTA」は Over-The-Air の略で、ケーブルをつながずにネットワーク越しにファームウェアを書き換える仕組みです（「OTA 更新」の節）。

## ハードウェア要件

| 項目 | 要件 |
| --- | --- |
| 基板 | ESP32-S3（動作確認は **ESP32-S3-DevKitC-1**。下の「おすすめの基板」を参照） |
| フラッシュ | **4 MB 以上**（OTA スロット × 2 で 3.4 MB 使用。デフォルト設定は **16 MB** 前提） |
| PSRAM | 不要 |
| ネットワーク | Wi-Fi（2.4 GHz）が使える LAN |

> 16 MB 以外のモジュールをお使いの場合は、開発環境セットアップ後に[フラッシュサイズの変更](#フラッシュサイズの変更)を参照してください。

### おすすめの基板

このプロジェクトは、ESP32 の開発元 Espressif の開発ボード **ESP32-S3-DevKitC-1** を対象にしています。エントリー向けの安価な基板で、Amazon をはじめ、通販サイトで容易に手に入ります。USB ケーブルで PC につなげば使い始められます。

作者は、Freenove 社の互換ボードを使っています（詳しくは「接続のしかた」を参照）。同じ構成（USB ポートが 2 つ、USB-UART 変換 IC、ESP32-S3-WROOM-1 モジュール）の互換ボードなら、同じように使えるはずです。

基板がむき出しのままだと、無線機まわりの金属や配線に触れてショートしたり、ほこりが付いたりするおそれがあります。必要に応じて、ケースに入れることをおすすめします。選ぶときは、次の点に気を付けてください。

- USB ポートが 2 つとも使えること（接続先は次の「接続のしかた」を参照）。
- 基板上の BOOT / RST ボタンに指が届くこと。
- 多くの製品では Wi-Fi のアンテナが基板に載っているため、金属製のケースは避け、樹脂製のものが無難です。

### 接続のしかた

ESP32-S3-DevKitC-1 には USB ポートが 2 つあります。使い分けは次のとおりです。

| ポート | 接続先 | 使うとき |
| --- | --- | --- |
| **USB-OTG** | **FTX-1**（音声と CAT） | ふだん使うとき |
| **USB-UART** | **PC** | 初期設定とフラッシュ書き込みのときだけ |

どちらがどちらかは、基板の表面に印刷されたシルク（文字）で、各ポートの横に書いてあります。Freenove の基板では 2 つのポートに表示があり、ほかの基板でも同様の表示がある可能性が高いです。つなぐ前に、表示を確認してください。

- FTX-1 とつなぐのは USB-OTG ポートです。ふだん使うときは、USB-UART ポートに PC をつなぐ必要はありません。
- USB-UART ポートは、Wi-Fi の設定などをシリアルメニューで行うときと、ファームウェアを書き込むときにだけ PC につなぎます（詳しくは「初回設定とフラッシュ書き込み」）。
- ふだん使うときは USB-OTG ポートを FTX-1 につなぐので、電源は **USB-UART ポート**につないでください。特別なものは要りません。そのあたりにある USB 充電器や USB バッテリーパックで足ります（消費電力は大きくありません）。
- **データ通信に対応した USB ケーブルを使ってください。** 充電専用のケーブルでは、どちらのポートでも動きません。
- **端子の形は基板によって違います。** 純正の ESP32-S3-DevKitC-1 の 2 つのポートは **Micro-USB** です（Espressif の[ユーザーガイド](https://docs.espressif.com/projects/esp-dev-kits/en/latest/esp32s3/esp32-s3-devkitc-1/user_guide_v1.1.html)を参照）。一方、FTX-1 側は **USB Type-C** です。基板側と FTX-1 側の端子に合わせて、ケーブルや変換アダプターを選んでください。
- **作者の構成（一例）:** Freenove 社の互換ボード（[FNK0099](https://store.freenove.com/products/fnk0099)、2 つとも **USB Type-C** のポート）と FTX-1 を、品質のよい**両端が USB Type-C のデータ通信対応ケーブル**（充電専用ではないもの）でつないでいます。両側が Type-C なので、このケーブル 1 本で足ります。
- ESP32-S3 が USB ホスト（親機）として動き、FTX-1 は読み出される側の機器になります。

> **インターネットには公開しないでください。** 本機は一定レベルのセキュリティに配慮していますが、インターネットにポートを公開すること（ルーターのポート転送など）は想定していません。必ず、信頼できる家庭内の LAN だけで使ってください。詳しくは「セキュリティ上の注意」をご覧ください。

## 開発環境のセットアップ

### 方法 A: Dev Container（推奨）

**Dev Container とは**、開発環境をまるごと Docker コンテナに入れた仕組みです。
ESP-IDF は導入手順が多く Python 環境の管理にもクセがあるため、
Dev Container を使うと「インストール済みの ESP-IDF v6.1 + openssl + Espressif 拡張機能」が
自動でセットアップされ、macOS / Linux / Windows を問わず同じ環境でビルドできます。

**必要なもの**:
- [Docker Desktop](https://www.docker.com/products/docker-desktop/)
- [VS Code](https://code.visualstudio.com/)（拡張機能: [Dev Containers](https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-containers)）

```bash
# 1. リポジトリを取得
git clone <このリポジトリの URL>

# 2. VS Code でこのフォルダを開き、「コンテナで再度開く」を選択するだけ
#    初回は Docker イメージ（espressif/idf:v6.1）のダウンロードに数分かかります
#    ESP-IDF v6.1、openssl、Espressif 拡張機能が自動でセットアップされます
```

USB シリアル（フラッシュ書き込み）には `--privileged` フラグが必要です（`devcontainer.json` に設定済み）。

> **注意**: Docker Desktop を使う macOS / Windows では、コンテナの中から USB シリアルポートが見えないことがあります。その場合は、コンテナの中でビルドだけを行い、書き込みは PC 側（コンテナの外）から行ってください。ビルドで作られる `build/` フォルダーは、PC 側からもそのまま見えます。書き込みの手順は「初回設定とフラッシュ書き込み」の「コンテナの外から書き込む場合」を参照してください。

### 方法 B: ローカル（macOS / Linux）

**必要なもの**:

| ツール | バージョン | 入手先 |
| --- | --- | --- |
| ESP-IDF | **v6.1** | [インストールガイド](https://docs.espressif.com/projects/esp-idf/en/v6.1/esp32s3/get-started/index.html) |
| openssl | 任意（システム付属で可） | macOS: `brew install openssl` / Ubuntu: `apt install openssl` |
| Python | 3.10 以上（ESP-IDF が起動時に確認し、足りなければ止まります） | macOS: `brew install python` / Ubuntu: `apt install python3 python3-venv` / [python.org](https://www.python.org/downloads/) |
| cmake | 3.22 以上（ESP-IDF に同梱） | 同上 |

ESP-IDF コンポーネント（`espressif/usb_host_uac`、`espressif/usb_host_cp210x_vcp`、`espressif/mdns` 等）は
`idf.py build` 時に [ESP Component Registry](https://components.espressif.com) から自動取得されます。

```bash
# 1. ESP-IDF v6.1 をインストール（初回のみ）
mkdir -p ~/esp && cd ~/esp
git clone -b v6.1 --recursive https://github.com/espressif/esp-idf.git
cd esp-idf && ./install.sh esp32s3

# 2. リポジトリを取得
git clone <このリポジトリの URL>
cd ftx1_companion

# 3. ESP-IDF 環境を有効化
source ~/esp/esp-idf/export.sh        # bash / zsh

# 4. ビルド（初回は依存コンポーネントの自動ダウンロードが走ります）
idf.py set-target esp32s3
idf.py build

# 5. ESP32-S3 に書き込む（PORT は macOS なら /dev/cu.usbserial-* など）
idf.py -p PORT flash monitor
```

> **注意**: `idf.py set-target` や `idf.py fullclean` を実行すると、
> TLS 証明書（`build/certs/`）が作り直されます。その後ブラウザで再度証明書を承認してください。

## フラッシュサイズの変更

デフォルトは 16 MB（[`sdkconfig.defaults`](sdkconfig.defaults) の `CONFIG_ESPTOOLPY_FLASHSIZE_16MB=y`）です。
お手元のモジュールが異なる場合は以下を変更してください。

1. [`sdkconfig.defaults`](sdkconfig.defaults) の `CONFIG_ESPTOOLPY_FLASHSIZE_16MB=y` を対応するサイズに変更
   （例: 8 MB なら `CONFIG_ESPTOOLPY_FLASHSIZE_8MB=y`）

2. ビルドし直す:

   **方法 A（Dev Container）**: VS Code のターミナル（コンテナ内）で実行
   ```bash
   idf.py fullclean && idf.py build
   ```

   **方法 B（ローカル）**: ESP-IDF 環境を有効化したターミナルで実行
   ```bash
   source ~/esp/esp-idf/export.sh
   idf.py fullclean && idf.py build
   ```

> パーティション構成（ota_0 / ota_1 各 1700 KB）は 4 MB 以上あれば変更不要です。

## 初回設定とフラッシュ書き込み

### 1. ビルドと書き込み

認証情報（Wi-Fi パスワードや OTA パスワード）はビルド時に埋め込む必要はありません（そのままビルド・フラッシュできます）。

ESP32-S3 の **USB-UART ポートだけ**を PC につないでから、次を実行します。`PORT` は、PC から見た ESP32-S3 のシリアルポート名に置き換えてください。

```bash
idf.py build
idf.py -p PORT flash monitor
```

| OS | `PORT` の例 | 調べ方 |
| --- | --- | --- |
| macOS | `/dev/cu.usbserial-0001` | `ls /dev/cu.usb*` |
| Linux | `/dev/ttyUSB0` | `ls /dev/ttyUSB*` |
| Windows | `COM3` | デバイス マネージャーの「ポート (COM と LPT)」 |

- ケーブルを抜き差しして、増えたり減ったりする名前が ESP32-S3 のポートです。
- ポートが現れないときは、基板の USB-UART チップ（CP210x）のドライバーが必要な場合があります。
- `idf.py monitor` は、`Ctrl` + `]` で終了します。

#### コンテナの外から書き込む場合

Dev Container の中から USB シリアルポートが見えないときは、コンテナの中でビルドし、書き込みだけ PC 側で行います。

```bash
# コンテナの中（ビルドと、書き込み用のファイルの作成）
idf.py build
idf.py merge-bin     # build/merged-binary.bin ができます

# PC 側（コンテナの外）。esptool を一度だけインストールして書き込みます
python3 -m pip install esptool
python3 -m esptool --chip esp32s3 -p PORT write-flash 0x0 build/merged-binary.bin
```

書き込みのあとは、Tera Term など好きなシリアルモニタ（115200 bps）で ESP32-S3 のポートを開いてください。

### 2. USB UART シリアル経由での対話型設定（NVS 保存）

Wi-Fi の接続先やパスワードなどの設定は、ESP32-S3 の **NVS**（Non-Volatile Storage。電源を切っても消えない、マイコン内の保存領域）に保存されます。
書き込み後または起動時、PC を USB-UART ポートにつなぎ、ESP32-S3 のシリアルモニタ（`idf.py monitor` や Tera Term など）を開きます。

- **初回起動時（Wi-Fi 未設定時）**: 自動的に設定メニューが開きます。
- **設定済み時**: 起動時に 3 秒間のカウントダウンが表示されます。`c` または `m` または `Enter` キーを押すと設定メニューに入ります。BOOT ボタンを押してもかまいませんが、**押すのは起動したあと**です。リセットや電源投入の最中に押したままにすると、ファームウェアではなく書き込みモードで起動してしまい、メニューは出ません。

```text
**************************************************
*       FTX-1 Companion Configuration Menu       *
**************************************************

==================================================
           CURRENT RUNTIME CONFIGURATION
==================================================
 1) Wi-Fi SSID       : (not set)
 2) Wi-Fi Password   : (empty / disabled)
 3) OTA User ID      : ota
 4) OTA Password     : (empty / disabled)
 9) Web User ID      : admin
 0) Web Password     : (empty / disabled)
 h) Host name        : ftx-1c.local
==================================================
Options:
  1: Set Wi-Fi SSID
  2: Set Wi-Fi Password
  3: Set OTA User ID
  4: Set OTA Password
  9: Set Web User ID
  0: Set Web Password
  h: Set Host name (mDNS / DHCP)
  5: Show passwords in plain text
  6: Save to NVS and Restart device
  7: Exit and continue boot without saving
  8: Erase NVS configuration (Reset to defaults)
--------------------------------------------------
Enter selection (0-9, h):
```

最低限、次の 3 つを設定してください。

1. `1` を入力して Wi-Fi の SSID を入力
2. `2` を入力して Wi-Fi のパスワードを入力（マスク表示）
3. `0` を入力して **Web パスワード**を入力（12 文字以上。ブラウザでログインするときのパスワードです）

続けて、必要に応じて次を設定します。

- `9`: Web 用の ID（既定は `admin`）
- `3` / `4`: OTA 更新用の ID とパスワード（パスワードは 12 文字以上）
- `h`: ホスト名（初期値は `ftx-1c`。詳しくは下記「ホスト名（mDNS）」参照）

最後に `6` を入力して「Save to NVS and Restart device」を実行します。**`6` で保存するまで、設定は反映されません。**

> **Web パスワードは必須です。** 設定しないと、ブラウザからは `Access is disabled (no password configured)`（HTTP 403）と表示されて、何も開けません。無認証で開いてしまうことはありません。
>
> SSID やパスワードに入力できるのは、半角の英数字と記号（ASCII）だけです。日本語など全角の文字は入力できません。

> **Git 公開時のメリット**: パスワード類はすべてマイコン内 NVS（不揮発性メモリ）に保存され、Git リポジトリやビルド成果物にプライベートな設定が一切残らないため、安全にパブリック公開やバイナリ共有が可能です。

### 3. ブラウザで動作を確認する

1. 再起動すると Wi-Fi に接続し、シリアルモニタのログに `Got IP: x.x.x.x` と `Open https://ftx-1c.local/` が表示されます。
2. FTX-1 の電源を入れ、ESP32-S3 の **USB-OTG ポート**を FTX-1 の USB につなぎます（「接続のしかた」を参照）。
3. 同じ LAN の PC / Mac のブラウザで、`https://ftx-1c.local/`（または `https://<ログに表示された IP>/`）を開きます。`http://` ではなく `https://` です。
4. 自己署名の証明書のため、**警告が表示されます**。LAN 内の自分の機器なので、内容を確認して続行（承認）してください（「自己署名証明書」の節を参照）。
5. ID とパスワードを聞かれます。ID は `admin`（`9` で変えていれば、その ID）、パスワードは `0` で設定した Web パスワードです。
6. **POWER / PLAY** ボタンを押すと、受信音の再生が始まります。ボタンの表示が `PWR OFF / STOP` に変わり、止めるときは同じボタンをもう一度押します。

うまくいかないときは「トラブルシューティング」を見てください。

## ホスト名（mDNS）

NVS にホスト名が保存されていない状態（初回起動時や、メニューの `8` で設定を消去した後）の初期ホスト名は `ftx-1c` です。
**mDNS**（Multicast DNS。同じ LAN の中で、DNS サーバーなしに「名前.local」でつなげる仕組み）により `https://ftx-1c.local/` で到達できます（[`espressif/mdns`](https://components.espressif.com/components/espressif/mdns) を使用）。
同じ名前は DHCP のホスト名（ルーターのクライアント一覧に表示される名前）にも使われます。

### ホスト名の変更（シリアルメニュー）

1. シリアルモニタでメニューを開きます（Wi-Fi 未設定なら自動、設定済みなら起動後 3 秒以内に `c` / `m` / `Enter`）。
2. `h` を入力し、`.local` を付けずにホスト名を入力します。何も入力せず Enter を押すと現在の値を保持します。
3. `6`（Save to NVS and Restart device）で保存して再起動します。**保存して再起動するまで変更は反映されません**。`7` で保存せずに抜けた場合は破棄されます。

```text
Enter selection (0-9, h): h
Enter Host name without ".local" [Current: ftx-1c] (a-z, 0-9, '-'; DEFAULT to reset; Enter to keep): radio-shack
-> Host name set to: radio-shack.local
```

- 使える文字は小文字 `a-z`・`0-9`・`-` のみで、先頭と末尾に `-` は使えず、63 文字以内です。大文字・`_`・空白・`.` を含む名前は「Rejected」と表示されて拒否され、元の値が残ります。
- `DEFAULT` と入力すると初期値 `ftx-1c` に戻ります（`8` の「Erase NVS configuration」でも他の設定と一緒に初期値へ戻ります）。
- NVS の値が何らかの理由で不正だった場合は、起動時に `ftx-1c` へ自動的に置き換えられます。
- 変更後の URL は、起動ログの `Open https://<ホスト名>.local/` でも確認できます。
- アクセス先の URL（ブックマーク、`ffplay` や `curl` のコマンドなど）は新しいホスト名に書き換えてください。以前の名前では到達できなくなります。

### 注意点

- **証明書の名前**: 証明書の SAN（`ftx-1c` / `ftx-1c.local`）はビルド時に決まります。ホスト名を変更すると、ブラウザは自己署名の警告に加えて「名前が一致しない」旨の警告も表示します。内容を確認して承認すれば使えますが、警告を出したくない場合は下記「自己署名証明書」の「別のホスト名の証明書を使う」を参照してください。
- **名前の重複**: 同じ名前の機器が LAN にある場合は、mDNS が `ftx-1c-2.local` のように自動で別名にすることがあります。複数台使うときは、台ごとに別のホスト名を設定してください。
- **ブラウザの状態**: ホスト名が変わると別のサイトとして扱われるため、ブラウザでの Basic 認証や証明書の承認はもう一度必要になります。
- macOS / iOS / Windows 10 以降 / 最近の Linux（avahi）は標準で `.local` を解決できます。
- 解決できない環境では、ログに出る IP アドレスで直接アクセスしてください。

## 使い方

### Web UI（ブラウザ操作画面）

ブラウザで `https://ftx-1c.local/` を開くと、以下の機能を備えた操作画面が利用できます。

- **VFO 表示と操作**:
  - **MAIN（VFO-A）**: スカイブルー（青系）で表示。L チャンネル音声（左耳）に対応。
  - **SUB（VFO-B）**: ミントグリーン（緑系）で表示。R チャンネル音声（右耳）に対応。
  - **バンド / モード切替**: 160m〜70cm バンドボタン、各種モードボタン（LSB, USB, CW, AM, FM, DATA-L, DATA-U, DATA-F, RTTY, PSK, C4FM）でワンクリック切替。
  - **ダイアル / ステップ**: マウスドラッグ、ホイール、ステップボタン（◀ / ▶）でのスムーズな周波数変更。
  - **VFO スワップ / コピー**: `A⇄B`（入れ替え）、`A→B`、`B→A` による設定複製。
- **スペクトラムスコープ & ウォーターフォール**:
  - 音声 FFT に基づくリアルタイム表示。モードに応じた SPAN 自動連動（CW: 1 kHz、AM/FM: 6 kHz、SSB/DATA等: 3.5 kHz）および手動切替（1k / 2.5k / 3.5k / 6k）。
- **疑似スケルチ**:
  - AM 向け「変動（直近 300 ms の振れ幅）」判定と FM/SSB 向け「レベル」判定。L/R 独立ゲート制御。
- **FT8 リアルタイムデコーダー & 世界地図**:
  - ブラウザ内 Web Worker による完全自動デコード。
  - `DECODER ON` で別ウインドウ（`/map`）の世界地図が開き、受信したグリッドロケーターを自動プロット。
- **録音機能（REC）**:
  - `REC MAIN` / `REC SUB` ボタンで、受信音をブラウザ側で WAV ファイルとして即座にダウンロード保存。
- **電源・システム制御**:
  - **POWER / PLAY**: 音声ストリーミングの開始・停止。
  - **REBOOT**: ESP32-S3 を安全に遠隔再起動（設定の即時再読込や動作リフレッシュ用）。
  - **RIG OFF**: FTX-1 本体の電源を CAT 経由でオフ（誤操作防止の確認ダイアログ付き）。

### エンドポイント

すべて Basic 認証が必要です（下記「セキュリティ上の注意」参照）。

| パス | 内容 |
| --- | --- |
| `/` | ブラウザ用プレーヤー |
| `/status` | ストリーム状態と診断値（JSON）。ファームのバージョン（`version`）、ビルド時刻（`build`）、音声形式、稼働時間、ヒープ（`heap_free` / `heap_min` / `heap_block`。PSRAM を有効にした場合はその分を含む）、内部 RAM のみのヒープ（`int_free` / `int_min` / `int_block`）、Wi-Fi の `rssi`、ストリームの送信統計（`stream.slow_sends` / `stream.max_send_ms` など） |
| `POST /cat` | 無線機の操作（周波数、モード、音量など。JSON、`X-Requested-With: ftx1` 必須） |

| `/stream.pcm` | 生の PCM（リトルエンディアン）。形式は `X-Sample-Rate` / `X-Channels` / `X-Bytes-Per-Sample` ヘッダーで通知 |
| `/stream.wav` | WAV ヘッダー付き（長さ不定）。外部プレーヤー向け |

```
ffplay -nodisp -tls_verify 0 https://ftx-1c.local/stream.wav
```

## 疑似スケルチ（ブラウザ側）

Yaesu FTX-1 の USB 音声は、無線機本体のスケルチが効かない（無信号時もノイズが出る）ことがあります。
そのため、再生ページ（[`main/index.html`](main/index.html)）で音声を判定して無音にする疑似スケルチを備えています。
**このページの再生にだけ効き、`/stream.pcm` や `/stream.wav` はそのままです。**

### 判定方式

| 方式 | 開く条件 | 用途 |
| --- | --- | --- |
| 変動（既定） | 直近 300 ms のレベルの振れ幅（最大 − 最小）が「変動しきい値」（既定 8 dB）を超える | AM |
| レベル | レベルが「しきい値」（既定 -34 dBFS）を超える。「反転」で逆にもできる | FM / SSB |

- AM の無信号ノイズは AGC により約 -27 dBFS で一定になり、受信中もレベルが同程度になることがあります。
  そのためレベルでは区別できず、AM では変動幅で判定します。
  実測では、無信号時の 300 ms 内の振れ幅は 99% が 6.4 dB 以下（最大 7.2 dB）、受信時は 10〜40 dB でした。
- 開いたあと 0.4 秒は保持し、語尾が切れないようにしています。ヒステリシスは 3 dB（レベル方式）、フェードは 10 ms です。
- 設定（有効／無効、方式、しきい値、判定に使う音声）はブラウザの localStorage に保存されます。

### L と R は別々に判定

FTX-1 の USB 音声は 48 kHz のステレオで、L が MAIN（VFO-A）、R が SUB（VFO-B）の音声です。周波数帯によってこの対応は変わりません。
既定の「L と R を別々に判定」では、チャンネルごとに独立したゲートを持ち、片方だけ受信しているときにもう一方は閉じたままです。
メーターの下に、各チャンネルのレベル、変動幅、開閉状態が表示されます。誤動作するときは、その数値を見てしきい値を調整してください。

- 変動しきい値を上げる: 無信号で誤って開くとき（目安 10〜12 dB）
- 変動しきい値を下げる: 受信しても開かないとき（目安 6 dB）
- 「R で判定し、両方を開閉」などを選ぶと、1 つのゲートで両チャンネルをまとめて開閉します。

### 制限

- 連続した声が 300 ms 以上ほぼ同じレベルで続くと、閉じることがあります（0.4 秒の保持で緩和）。
- 音声の内容による判定ではないため、変動の大きいノイズ（雷など）では開きます。
- 無線機の BUSY や S メーターを CAT で読む方式のほうが正確ですが、USB シリアル（CDC）のホスト対応が必要で、未実装です。

## FT8 デコーダーについて

ブラウザ側（[`main/index.html`](main/index.html)）に実装した FT8 リアルタイムデコーダーは、以下のオープンソースプロジェクトの仕様・実装を参考にしています。

| プロジェクト | 参照箇所 |
| --- | --- |
| **[ft8_lib](https://github.com/kgoba/ft8_lib)** by Karlis Goba (YL3JG) — MIT License | LDPC(174, 91) パリティ検査行列、CRC-14 多項式、8-FSK Gray マッピング、メッセージアンパック仕様 |
| **[WSJT-X](https://wsjt.sourceforge.io/)** by Joe Taylor (K1JT) et al. — GPLv3 | FT8 プロトコル仕様全般（Costas 配列、77-bit メッセージフォーマット、LDPC 符号パラメータ） |

ブラウザ上で JavaScript のみを用いて書いた FT8 フルスタックデコーダーで、上記プロジェクトを参考にしています。
上記プロジェクトのコードを直接移植・コピーしてはいない、というのが作者の認識ですが、
プロトコル定数（パリティ検査行列・Gray コード表・CRC 多項式・Costas シーケンス等）は
WSJT-X / ft8_lib が公開する仕様値をそのまま使用しています。

これらの先人の貢献なしには本プロジェクトは成立しませんでした。開発者の皆様に深く感謝いたします。

### デコード性能の設定

- 同期候補は上位 200 局、探索範囲は音声周波数 約 125〜3000 Hz です（混んだ 40 m のスロットを想定）。
- Costas の一致比が 3.5 未満の候補は復号を試みません（誤検出の抑制）。
- デコードは Web Worker(別スレッド)で 1 スロットに 1 回行います。混んだスロットでは Mac 上で 1.5〜1.8 秒かかりますが、音声再生と画面操作は止まりません。Worker は Blob URL から作るため、CSP に `worker-src blob:` を許可しています。
- 2 パス目（復号済みの信号を引いて再探索する方式）は未実装です。そのため、WSJT-X や ft8_lib より、強い局の裏に隠れた弱い局を拾えません。

### 時間同期（NTP）と伝送遅延への考慮

Wi-Fi やブラウザのオーディオ処理（バッファリング）を経由するため、無線機が受信した時刻とブラウザに音声データが届く時刻の間には不可避な伝送遅延（通常 100〜300 ms 程度）が発生します。本システムでは、この遅延を考慮して以下の設計を行っています。

- **DT（時間オフセット）探索による遅延の吸収**: FT8 は電波伝搬遅延や各局の時計のズレを想定したプロトコルであり、デコーダーは同期探索（Costas 配列探索）において時間オフセット（DT）を探索します。ネットワーク伝送遅延はこの DT のプラス側シフト（通常 +0.1〜+0.4 秒程度）として自然に吸収されるため、復号の成否には影響しません。
- **デコード開始タイミングの調整（14.0 秒）**: FT8 の 15 秒スロットにおいて、標準的な送信は 0.5 秒から 13.14 秒の間（DT=0 の場合）に行われます。伝送遅延やバッファによって末尾のシンボルが遅れて届くことを考慮し、本実装ではスロット境界（15.0 秒）直前ではなく **14.0 秒時点** で 15 秒分の波形を切り出して Web Worker に渡しています。これにより、遅延したシンボルを取りこぼさずに復号できます。
- **波形の連続性**: ネットワークのジッター（パケット到着のゆらぎ）が生じても、受信側リングバッファにはサンプリングレート（48 kHz / 6.4 kHz）通りの連続した時系列データとして蓄積されるため、シンボル間の相対的な間隔や位相関係が崩れることはありません。

### FT8 世界地図

![FT8 世界地図ウインドウ: グリッドロケーターの位置に局をプロットし、下にデコードした局の一覧を表示（画面内のコールサインはダミーです）](docs/ft8_map.png)

`DECODER ON` を押すと別ウインドウ（`/map`）で世界地図が開き、デコードしたメッセージに含まれるグリッドロケーター（4 桁）の位置に局をプロットします。

- コールサインは地図上には常時表示せず、マーカーをクリックすると、グリッド・SNR・距離・方位と合わせて表示します。一覧の行をクリックしても選択でき、画面外の局は表示位置へ移動します。同じグリッドに複数の局が重なっている場合は、クリックするたびに順に切り替わります。選択の解除は、何もない場所のクリックか Esc キーです。
- 地図は拡大・縮小とドラッグでの移動ができます（最大 ×40）。マウスホイール、ダブルクリック、ヘッダーの `+` / `−` で拡大・縮小し、`FIT` で全体表示に戻ります。拡大するとグリッドスクエア（`PM95` など）の区画と名前が現れます。
- ヘッダーの `My grid` に自局のグリッド（4 桁または 6 桁）を入力して `SET` を押すと、距離・方位の表示と大圏線の描画が有効になります。入力値はブラウザの `localStorage` に保存されます。
- 局の色は、MAIN / SUB ではなくバンド（160 m〜6 m）ごとに付けます。凡例には、今表示されているバンドだけが並びます。QSO の線は琥珀色、自局は赤です。一覧には BAND 列があります。
- グリッドを含むメッセージ（CQ、最初の呼び出し）のみがプロット対象です。レポート交換・`RR73`・`73`、およびハッシュ化されたコールサインは対象外です。
- 古いスポットは薄くなり、15 分で消えます。地図ウインドウを閉じて開き直すと、それまでのスポットが復元されます。
- 海岸線は [Natural Earth](https://www.naturalearthdata.com/)（パブリックドメイン）50m の land データを 0.02 度で間引き、ベクターのまま [`main/map.html`](main/map.html) に埋め込んでいます（約 220 KB）。拡大しても輪郭が粗くならず、インターネット接続なしで動作します。
- ポップアップがブロックされた場合は、アドレスバーのブロック表示からこのサイトのポップアップを許可してください。

## OTA 更新

ネットワーク経由でファームウェアを書き換えられます。

```bash
source ~/esp/esp-idf/export.sh   # Dev Container 内では不要
idf.py build
read -rs PW   # パスワードを入力（コマンド履歴に残りません）
curl -k -u "ota:$PW" -H "X-Requested-With: ftx1" -X POST --data-binary @build/ftx1_companion.bin https://ftx-1c.local/ota
unset PW
```

`X-Requested-With: ftx1` ヘッダーは CSRF 対策のため必須です（無いと 403）。

- パスワードはシリアルメニューの `4` で設定します（NVS に保存、12 文字以上）。上のように `read -rs` で読み込むと、コマンド履歴に残りません。`ota:` を含めて 95 文字以下にしてください。
- 認証は HTTP Basic で、HTTPS 上でだけ送られます。比較は定数時間で、失敗すると 1 秒待たせます。
- 受信したイメージは `esp_ota_end()` が検証します（マジック、チップ、チェックサム、SHA-256）。壊れたイメージは 400 で拒否され、動作中の版には影響しません。
- パーティションは 1700K の OTA スロットが 2 つです（`ota_0` / `ota_1`、factory なし）。更新はもう一方のスロットへ書き込み、成功したら切り替えて再起動します。
- ロールバックが有効です。新しい版は、Wi-Fi 接続と Web サーバー起動に成功した時点で「確認済み」になります。
  起動に失敗し続ける版は確認されないまま再起動され、ブートローダーが前の版に戻します。
- 更新中に別の `POST /ota` が来ると 409 を返します。
- **パーティション構成を変えたあと（単一アプリ構成からの移行など）の最初の 1 回は、シリアルで `idf.py flash` が必要です。**
- 検証済み: 認証失敗（401）、壊れたイメージ（400）、正常な更新（`ota_0` ↔ `ota_1`）、再起動後の確認。
  未検証: ロールバックの実動作、USB 音声を配信中の更新。

## 自己署名証明書

HTTPS 用の自己署名証明書（EC P-256、有効期間 2 年、SAN: `ftx-1c` / `ftx-1c.local`）は、
ビルド時に `openssl` で `build/certs/` へ自動生成され、ファームウェアに埋め込まれます。

- 秘密鍵と証明書は `build/certs/` に置かれ、`.gitignore` 済みなのでコミットされません。
- `idf.py fullclean` や `idf.py set-target` を実行すると証明書も作り直され、ブラウザの警告を再度承認する必要があります。
- 同じビルドディレクトリで再ビルドするかぎり、同じ証明書が使われます。
- TLS のバージョンは mbedTLS が提供する 1.2 / 1.3 がネゴシエートされます。
- 自己署名のためブラウザは警告を出します。信頼できるのは、LAN 内の自分のデバイスに接続している場合だけです。

### 別のホスト名の証明書を使う

シリアルメニューでホスト名を変えても、証明書の SAN は変わりません。名前不一致の警告を避けたい場合は、証明書も作り直します。

1. [`main/CMakeLists.txt`](main/CMakeLists.txt) の `-subj` の `CN=` と `-addext "subjectAltName=..."` を新しいホスト名に書き換えます（例: `DNS:radio-shack.local,DNS:radio-shack`）。
2. `build/certs` を削除して再ビルドし、ファームウェアを書き込みます。
3. シリアルメニューの `h` で同じホスト名を設定し、保存して再起動します。

## セキュリティ上の注意

### 認証

すべてのエンドポイント（`/`、`/map`、`/status`、`/cat`、`POST /reboot`、`/stream.*`、`POST /ota`）は HTTP Basic 認証で保護しています。HTTPS 上でだけ使ってください。

- Web 用の ID とパスワードは、シリアルメニューの `9`（Web User ID、既定 `admin`）と `0`（Web Password）で設定し、NVS に保存します。
- パスワードは 12 文字以上が必須です。ID に `:` と空白は使えません。
- Web パスワードが未設定の場合は、OTA の ID / パスワードで代用します。両方未設定のときは、アクセスを 403 で拒否します（無認証で開くことはありません）。
- 同じクライアント IP から 5 回失敗すると 60 秒ロックし、429 を返します。
- 状態を変える要求（`POST /cat`、`POST /reboot`、`POST /ota`）は CSRF 対策として、`X-Requested-With: ftx1` ヘッダーと、同一オリジンの `Origin` / `Sec-Fetch-Site` を要求します。
- 応答には `nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer`、CSP を付けます。

### 電波を送信させないための制限

ネットワーク経由で無線機を送信状態にできないよう、ESP32 から無線機へ送れる CAT コマンドを絞っています（[`main/cat.c`](main/cat.c)）。

- ブラウザは CAT コマンドを生成しません。`POST /cat` は JSON で `target` / `freq` / `mode` / `vol` / `sq` / `notch` / `notch_hz` / `power` / `action` だけを受け付けます。
  未知のキー、重複キー、`cmd`（生コマンド）は 400 で拒否します。`action` は `swap` / `copy_main_to_sub` / `copy_sub_to_main` のみです。
- ESP32 から無線機へ送るコマンドは許可リスト方式です（`ID` `SV` `AB` `BA` `AI` `RI` `RM` `PS` `FA` `FB` `MD` `AG` `SQ` `BP` `EX`）。
  `EX` は DATA-USB の `USB OUT LEVEL` を 100 にする書き込み（`EX010411`）だけを通します。
  `TX` `MX` `KY` `PB` `VX` `PC` などの送信につながるコマンドは、コード上に呼び出し経路がなく、許可リストでも遮断されます。
  このため、本ファームウェアには無線機を送信状態にする操作がありません。
- 周波数の設定は、範囲を確認します。FTX-1 が受け付ける 30 kHz〜470 MHz（30000〜470000000 Hz）の値だけを無線機に送り、範囲外の値は拒否します。
- 二重の保険として、無線機本体の `RPTT SELECT` / `TX INHIBIT` の設定も検討してください。
- ESP32 を経由しない送信（マイクの PTT、本体操作）は防げません。

### 入力検証とビルド設定

- リクエストのボディ長、JSON、USB 音声の形式（チャンネル数、サンプルサイズ、サンプルレート）を検証し、境界を超える値は拒否します。
- FT8 のデコード結果などは HTML エスケープしてから表示します（XSS 対策）。
- スタック保護（`CONFIG_COMPILER_STACK_CHECK_MODE_STRONG`）とヒープポイズニング（`CONFIG_HEAP_POISONING_LIGHT`）を有効にしています。

### 残るリスク

- Secure Boot、フラッシュ暗号化、NVS 暗号化は未対応です。デバイスを物理的に入手されると、NVS のパスワードを読まれる可能性があります。
- HTTPS の秘密鍵はファームウェアに埋め込まれています。自己署名証明書のため、初回は警告の承認が必要です。
- 実運用の前に、信頼された CA の証明書への置き換えを検討してください。
- **インターネットへ公開しないでください。** ルーターのポート転送などで、外部からこの機器に届くようにしないでください。本機は一定レベルのセキュリティに配慮していますが、インターネットに公開される前提では作っていません。信頼できる LAN 内だけで使ってください。
- 外出先から使いたい場合も、ポートを開けるのではなく、VPN など、LAN の中に安全に入る方法を使ってください。

## 制限事項

- 同時にストリームを受けられるクライアントは 1 つです。
- 音声入力デバイスは 1 台のみ使用します（2 台目以降は無視）。
- UAC 1.0 のデバイスのみ対応しています。
- ブラウザ再生は数百 ms 程度の遅延があります。
- スマートフォンのブラウザには対応していません。画面は PC / Mac のブラウザ向けに作っています。

## トラブルシューティング

### 書き込みとシリアルメニュー

- シリアルポートが見つからない、`Failed to connect` と出る: ケーブルが充電専用ではないか、PC をつないだのが **USB-UART ポート**（USB-OTG ではない側）かを確認してください。
- Linux で `Permission denied` と出る: Ubuntu などでは `sudo usermod -aG dialout $USER` を実行し、ログインし直してください（ディストリビューションによってグループ名は異なります）。
- ログに `waiting for download` と出て止まっている: リセットや電源投入のときに **BOOT ボタンを押したままだった**ため、書き込みモードに入っています。BOOT ボタンを離してから RST（リセット）ボタンを押すと、通常どおり起動します。
- 起動ログに `Wi-Fi connection failed` と出て止まった: 30 秒待っても Wi-Fi につながらなかった状態です。RST ボタンを押して再起動し、表示される 3 秒のカウントダウンのうちに `Enter` を押してメニューに入り、SSID（`1`）とパスワード（`2`）を直してください。5 GHz 専用の SSID には接続できません。

### ブラウザ

- `Access is disabled (no password configured)`（HTTP 403）と表示される: Web パスワードが未設定です。シリアルメニューの `0` で設定してください。
- ログインできない（401）、または `Too many failed attempts`（429）と表示される: ID とパスワードを確認してください。同じ端末（IP アドレス）から 5 回続けて失敗すると、60 秒間は受け付けません。

### 音声と接続

- `No USB audio device streaming`（HTTP 503）: USB 音声入力デバイスが接続・認識されていません。シリアルログの `usb_audio` を確認してください。
- 音が途切れる: `/status` を開いて次を確認してください。
  - `heap_min` が数 KB まで下がっている: 内部 RAM の不足です。TLS バッファを必要なときだけ確保する設定（`CONFIG_MBEDTLS_DYNAMIC_BUFFER`）を既定で有効にしています。
  - `stream.max_send_ms` が約 330 ms（リングバッファ 64 KB 分）を超える、または `rssi` が -75 dBm より悪い: Wi-Fi の電波状況を確認してください。
  - ブラウザのコンソールで `audioDiag` を実行すると、受信待ち（`maxReadMs`）とブラウザ側の処理時間（`maxProcMs`）を見られます。
- `ftx-1c.local` が開けない: 同じ LAN／サブネットにあるか確認し、ログの IP アドレスで直接開けるか試してください。
- ブラウザが接続を拒否する: `http://` ではなく `https://` で開いているか確認してください。
- デバイスが認識されない: UAC 1.0 でない、またはハブ経由の給電不足の可能性があります。
- VFO A / VFO B の周波数表示とスコープ（ウォーターフォール）の位置が一致しない: ごくまれに起こります。そんなときは優しい心を持って、**A→B (A=B)** ボタンを押して設定し直してください。

### ほかの無線機で使うには（ヒント）

このプロジェクトは FTX-1 専用で、動作確認も FTX-1 でしかしていません。複数の無線機に対応するライブラリに育てるつもりもありません。ご自身のフォークでほかの無線機を試したい場合は、[`main/cat.c`](main/cat.c) の冒頭のコメントから始めてください。ファームウェアが送る CAT コマンドの全部を、パラメーターと、読み取る応答とあわせて一覧にしてあるので、その無線機の CAT マニュアルと見比べられます。同じコメントに、無線機ごとに違う箇所（許可リスト、周波数の範囲、モードの表、応答の解析、`EX` のメニュー項目、MAIN / SUB の前提、CAT ポートの見つけ方）も挙げています。何を変えても、無線機を送信状態にしうるコマンドが許可リストを通らないことを、必ず確認し直してください。

## 用語集

このドキュメントに出てくる専門用語の簡単な説明です。

### USB と基板

- **USB-OTG ポート**: ESP32-S3 の、FTX-1 につなぐポートです。ESP32-S3 が USB ホスト（親機）として動きます。
- **USB-UART ポート**: PC をつなぐ（書き込み、シリアルメニュー）ためのポートです。電源にも使います。
- **UAC（USB Audio Class）**: USB オーディオの標準規格です。FTX-1 は、これにより PC に「USB マイク」のように見えます。
- **CDC**: USB でシリアル通信を行うための標準クラスです。
- **CP210x**: Silicon Labs 社の、USB とシリアルの変換チップです。FTX-1 の CAT ポートが使っています。基板の USB-UART ポートにも使われることがあり、その場合、PC にドライバーが必要なことがあります。
- **CAT（Computer Aided Transceiver）**: コンピューターから無線機を制御する仕組みです。本プロジェクトでは、周波数やモードの読み出しと設定に使います。

### ネットワーク

- **mDNS**: IP アドレスの代わりに、`ftx-1c.local` のような名前で機器に届けられるようにする仕組みです。
- **DHCP**: ルーターが、IP アドレスを自動で割り当てる機能です。
- **LAN**: 家庭内のネットワークです。
- **TLS / HTTPS**: ブラウザと機器の通信を暗号化する仕組みです。
- **SAN（Subject Alternative Name）**: 証明書に書かれたホスト名の一覧です。開いた名前がここになければ、ブラウザが警告を出します。

### セキュリティ

- **CSRF**: 別の Web ページから、意図しない要求をブラウザに送らせる攻撃です。`X-Requested-With` ヘッダーで防いでいます。
- **XSS**: Web ページに仕込んだスクリプトを実行させる攻撃です。表示する文字列をエスケープして防いでいます。
- **CSP（Content Security Policy）**: ページが読み込み・実行してよいものを、ブラウザに伝える規則です。
- **Basic 認証**: ID とパスワードによる簡易なログイン方式です。HTTPS と併用しています。

### ファームウェアと開発

- **NVS（不揮発性ストレージ）**: マイコン内の、電源を切っても内容が残る領域です。Wi-Fi の設定やパスワードを保存します。
- **OTA（Over-The-Air）**: ケーブルを使わず、ネットワーク経由でファームウェアを更新することです。
- **ESP-IDF**: ESP32 の公式の開発環境（SDK）です。
- **Dev Container**: Docker コンテナにまとめた開発環境です。
- **FT8**: 弱い信号でも交信しやすいデジタルモードです。ブラウザが受信音から解読します。
